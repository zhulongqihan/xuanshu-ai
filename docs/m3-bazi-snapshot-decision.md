# M3 八字快照与档案修订决策

状态：已采用

更新日期：2026-08-21

## 目标

让“人物档案 -> 归一化出生记录 -> 八字/大运计算 -> 页面展示”能够被复算、追溯和审计，
同时保证修改出生信息不会覆盖旧结果。

## 决策

1. `profile_birth_records` 是不可变出生记录。修改档案时只把旧记录标记为非当前，新增递增
   `revision`；原始输入、归一化输入、输入哈希、依赖版本、来源和警告全部随 revision 保存。
2. 同一人物、同一规范化输入哈希不重复生成出生 revision；只修改显示名称不改变出生记录。
3. 八字快照必须同时绑定 `profileId`、`birthRecordId`、`inputHash`、八字引擎版本和规则集版本。
   规则或出生记录变化时不复用旧快照；同一绑定条件下复用已经通过完整性校验的快照。
4. 快照 payload 同时保存八字事实层、大运结果、计算轨迹、警告和逐规则 `EvidenceRef`。证据映射
   缺失时计算失败，不生成缺少来源的用户可见结果。
5. 快照读取不仅按输入哈希筛选，还会再次比较数据库元数据与 payload；检测到篡改或不一致时拒绝
   读取，不能静默当作“没有快照”。

## 当前 payload 边界

- `chart.schemaVersion=1`。
- `chart.birthRecordId` 指向不可变出生记录。
- `chart.bazi` 使用 `baziCalculationSchema`；`chart.luck` 使用 `baziLuckCalculationSchema`。
- `chart.evidence` 覆盖八字和大运输出中的全部 `ruleIds`。
- AI 解读不写入确定性八字快照；AI 结果将在后续咨询记录中单独保存模型、提示词版本和声明。

## 未决事项

- 旧版无 `birthRecordId` 的遗留快照保留为迁移兼容数据，不作为新八字页面的有效快照。
- 当前仍只实现八字快照；紫微、老黄历和六爻在各自确定性引擎完成后使用独立 payload，不能共用八字规则集。
