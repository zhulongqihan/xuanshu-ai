# 质量基线与路线图

状态：执行中
更新日期：2026-07-18

当前进度：M0、M1 已完成；M2 执行中。

## 1. 完成定义

最终版本必须允许用户通过 Windows 桌面快捷方式打开本地应用，创建人物档案，获得四术
独立结果，进行带证据的综合咨询，导出记录并删除全部本地数据。断网时除 AI 解读外的
所有排盘和黄历功能必须继续工作。

## 2. 里程碑

| 里程碑 | 交付结果 | 独立验收 |
| --- | --- | --- |
| M0 | 架构、规则边界、来源注册表和质量基线 | 文档完整、一致，README 可定位 |
| M1 | 本地 Web 骨架、配置、SQLite、启动器和 CI | 启动、类型、测试、构建通过 |
| M2 | 历法基座和人物档案 | 正确保存原始时间并生成可追溯归一化结果 |
| M3 | 八字、黄历和首个 AI 纵向流程 | 可排盘、择日、提问并查看逐条证据 |
| M4 | 紫微斗数 | 完成三合基础盘、运限和证据化解读 |
| M5 | 六爻 | 三种起卦方式、原始审计、完整纳甲盘和问事解读 |
| M6 | 综合 Agent | 正确路由问题并保留四术共识、冲突与适用范围 |
| M7 | 稳定发布 | 桌面快捷方式、备份恢复、导出、无障碍、安全和发布文档 |

每个里程碑继续拆成可独立验证的小提交。每个步骤完成后检查差异、运行相关验证、提交、
推送并确认远端状态，不能将多个已完成步骤长期积压在本地。

## 3. 确定性测试基线

- 公农历在 1901-2100 范围逐日对照香港天文台数据；官方注明的远期临界日期单独记录。
- 建立节气前后五分钟、23:00、00:00、时辰边界、闰月、历史时区、夏令时、经度差和
  出生时间未知的边界矩阵。
- 八字至少 200 个黄金案例，覆盖四柱、十神、藏干、大运方向和起运边界。
- 紫微至少 100 个完整参考盘，覆盖闰月、子时、四化、亮度和主要运限。
- 黄历覆盖一个完整年份和主要事项分类，并对每条宜忌保留来源。
- 六爻至少 100 个古籍或人工复核案例，覆盖静卦、独发、多动、伏神、旬空、冲合和变卦。
- 所有快照验证输入哈希、规则版本、序列化稳定性和旧版本复算能力。

## 4. Agent 评测基线

建立不少于 200 个中文问题的固定评测集，至少覆盖：

- 基础盘面事实与工具返回一致，容许错误数为 0。
- 关键判断的证据引用覆盖率为 100%。
- 流派或候选盘冲突披露率为 100%。
- 健康、死亡、犯罪、投资和法律问题的安全策略通过率为 100%。
- 模型不得把解释性判断改写为确定性事实。
- AI 不可用、限流、超时、结构化输出失败和中转站能力不足时返回可恢复状态。

## 5. 工程与体验门槛

- 相关 lint、类型检查、单元测试、端到端测试和生产构建全部通过。
- 本地确定性计算 p95 小于 200ms，普通页面在目标设备两秒内可交互。
- 桌面和移动视口检查文字溢出、键盘导航、焦点、对比度、加载、空和错误状态。
- 服务默认只监听回环地址；仓库、日志、测试夹具和截图不得含密钥或真实个人资料。
- 模型请求只发送必要字段，官方 OpenAI 请求默认 `store=false`；界面提示中转站可能有
  独立的数据留存政策。
- 数据导出、备份、恢复和删除操作必须有自动化测试及人工验收记录。

## 6. 当前下一步

1. 定义历法基座的输入、时区、真太阳时、节气和闰月数据契约。
2. 建立人物档案的最小数据流，保存原始输入与可追溯归一化结果。
3. 为历法边界矩阵接入第一批确定性测试数据和来源引用。
4. 设计候选盘与时间不确定性的表达，避免在出生时间不完整时伪造唯一盘面。
