## 3. 确定性测试基线

- 公农历在 1901-2100 范围逐日对照香港天文台数据；官方注明的远期临界日期单独记录。
- 建立节气前后五分钟、23:00、00:00、时辰边界、闰月、历史时区、夏令时、经度差和
  出生时间未知的边界矩阵。
- 八字至少 200 个黄金案例，覆盖四柱、十神、藏干、大运方向和起运边界。
- 紫微至少 100 个完整参考盘，覆盖闰月、子时、四化、亮度和主要运限。
- 黄历覆盖一个完整年份和主要事项分类，并对每条宜忌保留来源。
- 六爻至少 100 个古籍或人工复核案例，覆盖静卦、独发、多动、伏神、旬空、冲合和变卦。
- 所有快照验证输入哈希、规则版本、序列化稳定性和旧版本复算能力。

## 4. Agent 评测基线

建立不少于 200 个中文问题的固定评测集，至少覆盖：

- 基础盘面事实与工具返回一致，容许错误数为 0。
- 关键判断的证据引用覆盖率为 100%。
- 流派或候选盘冲突披露率为 100%。
- 健康、死亡、犯罪、投资和法律问题的安全策略通过率为 100%。
- 模型不得把解释性判断改写为确定性事实。
- AI 不可用、限流、超时、结构化输出失败和中转站能力不足时返回可恢复状态。

## 5. 工程与体验门槛

- 相关 lint、类型检查、单元测试、端到端测试和生产构建全部通过。
- 本地确定性计算 p95 小于 200ms，普通页面在目标设备两秒内可交互；当前 Windows 基准的四术 p99 均低于 25ms，见 [性能基线](./performance-baseline-20260821.md)。
- 桌面和移动视口检查文字溢出、键盘导航、焦点、对比度、加载、空和错误状态。
- 服务默认只监听回环地址；仓库、日志、测试夹具和截图不得含密钥或真实个人资料。
- 模型请求只发送必要字段，官方 OpenAI 请求默认 `store=false`；界面提示中转站可能有
  独立的数据留存政策。
- 数据导出、备份、恢复和删除操作必须有自动化测试及人工验收记录。
