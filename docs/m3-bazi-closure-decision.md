# M3 八字确定性闭环决策

状态：已采纳
更新日期：2026-08-21

## 1. 本阶段目标

本阶段先把已有的八字事实层和精确时间大运做成可用的本地产品闭环：

`人物档案 -> 出生记录 -> 八字候选 -> 大运 -> 证据与警告 -> 本地快照 -> 命盘页面`

本阶段不实现老黄历、紫微斗数、六爻、综合 Agent 或模型咨询。它们保留在 M3.5、M3.6
及后续里程碑，不得用占位结果提前伪装完成。

## 2. 候选盘交互政策

- 民用时间是主盘。
- 真太阳时、约略时间和 DST fold 产生的候选作为并列候选展示，不要求用户先选择一个流派或
  时刻才能查看结果。
- 每个候选必须保留 `timeBasis`、`timePrecision`、`dayBoundary`、来源时间窗、fold、
  警告和输入哈希。
- 候选之间不计算“平均盘”，不把差异隐藏为单一结论。
- 只有跨所有候选都成立的事实，才可以在 UI 中标记为稳定事实；本阶段暂不生成解释性判断。

## 3. 约略时间大运政策

- 精确出生时间返回单点起运值；约略出生时间返回每个候选的起运范围；未知时间返回不可用和
  结构化原因。
- 范围计算以候选保存的有效分钟来源窗口为输入，不能根据展示用年龄反推范围。
- 候选窗口跨越节气、立春、DST fold 或方向变化时必须分段；不同方向或参考节气不得合并。
- 继续使用 `bazi-ziping-v1` 的“三日折一年”规则，保留物理距离秒数和象征年龄分解值。
- 交运公历点由出生地确认的 IANA 时区和候选来源时间计算，同时保存本地时间和 UTC instant。
- 约略候选的最小、最大值均来自实际有效来源分钟；不得生成窗口外的推测值。

## 4. 快照与证据政策

- 新生成的八字快照必须绑定 `profileId`、`birthRecordId` 和 `inputHash`。
- 读取或写入快照前，必须验证输入哈希、规则版本和结构化 payload。
- 同一出生记录、引擎版本和规则版本的快照可复用；出生记录或版本变化时生成新快照。
- 规则 ID 必须能映射到具体来源定位。`lunar-typescript` 只能标记为交叉验证参考，不作为
  正式规则来源。
- UI 默认展示事实、候选、警告和证据；旺衰、格局、用神等解释性规则必须在独立版本中实现。

## 5. M3.1-M3.3 验收门槛

- 精确时间、约略时间、未知时间均有明确状态。
- 约略时间跨 23:00、节气、DST fold 和 DST gap 时结果可追溯。
- 起运年龄和交运公历点可表达单点或范围，且保留原始秒数。
- 档案 revision 不覆盖旧出生记录；快照始终指向对应 birth record。
- `/charts` 可以从人物档案进入，显示民用主盘、候选盘、大运、警告和来源证据。
- 没有模型配置时，八字闭环仍可离线工作。
- 桌面、390px 移动视口、键盘导航、加载、空和错误状态通过验收。
