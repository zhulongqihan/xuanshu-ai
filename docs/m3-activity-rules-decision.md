# M3.5 黄历事项级规则决策

状态：active
更新日期：2026-08-21

## 目标

让黄历页面从“只展示日期事实”推进到“针对具体事项输出可解释候选信号”，同时避免制造一个没有依据的综合吉凶分数。

## 首版规则

- 支持出行、搬迁、签约、祭祀四类事项。
- 每类事项只使用建除十二神作为首版筛查层，输出 `favorable`（适合候选）、`caution`（谨慎）、`conflict`（冲突）或 `insufficient`（资料不足）。
- 每个事项保存 `factors`，当前至少包含建除因素、信号、说明和规则 ID；全局 evidence 与 ruleIds 必须覆盖这些规则。
- 规则集合是事项特定的：例如“满”进入搬迁支持集合，但不自动推导为所有事项都适合；“破/闭”进入四类事项的首版冲突集合。
- 页面明确展示“候选信号”语义，不生成吉利指数，不把事项筛查当作科学结论。

## 不纳入本阶段

- 值神、二十八宿、神煞、日时宜忌、方位和个人八字冲合尚未加入正式判断。
- 首版不合并多个事项，也不自动替用户决定日期；缺少完整规则时保留谨慎/资料不足状态。
