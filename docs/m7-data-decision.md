# M7 本地数据管理决策

状态：已完成首个可验证闭环
更新日期：2026-08-21

## 目标

用户可以在设置页下载本机数据的 JSON 备份，在更换设备或恢复环境时导入，并在确认后清空本机全部数据。出生资料、盘面、咨询、消息、六爻案例和应用元数据都纳入同一份备份，不把数据库文件路径或模型服务作为用户操作前提。

## 设计约束

- 备份格式固定为 `schemaVersion: 1`，表名和字段白名单由服务端维护。
- 恢复先完成 JSON、字段类型、字段集合和 SQLite 约束校验，再进入清空与写入事务；校验失败或写入失败都不改变现有数据。
- 写入顺序遵守外键关系：人物档案 → 出生记录 → 盘面 → 咨询 → 消息；六爻案例和应用元数据单独恢复。
- 清空动作显式确认，删除消息、咨询、六爻案例、盘面、出生记录、人物档案和元数据。
- 备份下载使用 `no-store` 和附件响应头；界面明确提醒备份包含出生日期、时间和地点等敏感资料。
- 当前只接受版本 1；未来版本默认拒绝恢复并保留现有数据，不做未经验证的自动降级或字段猜测。

## 验收

- `apps/web/test/data-backup.test.ts`：完整数据导出、清空、恢复，以及非法字段在清空前被拒绝。
- 同一测试文件覆盖未来 `schemaVersion` 的安全拒绝，作为跨版本兼容策略的回归门槛。
- Web 全量测试：9 个测试文件、34 个测试通过。
- 生产构建识别 `/api/backup` 动态路由。
- 浏览器验收：设置页桌面/移动视口可用；390px 宽度下 `scrollWidth=390`，无横向溢出。
- 下载接口返回 `200`、`application/json`、附件文件名和 `schemaVersion=1`，包含 7 张数据表。
- Windows PowerShell 验收：脚本解析通过，安装脚本在隔离目录生成 `.lnk`，启动脚本通过 `/api/health` 健康检查；测试进程随后已停止。
